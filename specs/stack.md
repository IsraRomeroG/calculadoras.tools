# Stack — calculadoras.tools

## Overview

**calculadoras.tools** is a Spanish-language calculator platform built for performance, SEO, and scalability. The architecture prioritizes static generation and client-side logic, reserving backend services only for cases that genuinely require server-side processing.

---

## Frontend

| Layer | Technology | Notes |
|---|---|---|
| Framework | [Astro](https://astro.build/) | Static site generation (SSG) by default |
| Styling | [Tailwind CSS](https://tailwindcss.com/) | Utility-first CSS framework |
| Language | TypeScript / JavaScript | Calculator logic runs client-side |
| Rendering strategy | Static-first | Most calculators are fully static; no server round-trips |

### Guiding principles
- The vast majority of calculators run entirely in the browser (no API calls needed).
- Astro's island architecture is used selectively to hydrate interactive components only where necessary.
- Pages are pre-rendered at build time for maximum performance and SEO.

---

## Backend

| Layer | Technology | Notes |
|---|---|---|
| Framework | [Spring Boot](https://spring.io/projects/spring-boot) | Java-based microservices |
| Architecture | Microservices | One service per domain when backend is required |
| Language | Java | |
| API style | REST | JSON over HTTP |

### Guiding principles
- Backend microservices are only introduced when a calculator cannot be handled client-side (e.g., real-time data, sensitive computations, third-party integrations).
- Each microservice is independently deployable and scoped to a single responsibility.

---

## Database

| Aspect | Decision |
|---|---|
| Default | Relational (SQL) |
| Alternative | Non-relational (NoSQL) — evaluated case by case |
| Strategy | No global database defined at launch; each microservice owns its data store when needed |

### Guiding principles
- The initial default is a relational database for any persistence needs.
- Non-relational databases are considered on a per-case basis depending on the data shape and access patterns.

---

## Infrastructure & Deployment

| Layer | Technology | Notes |
|---|---|---|
| Phase 1 — Frontend | Cloudflare CDN | 100% static site; global edge delivery |
| Phase 2+ — Backend | AWS | Cloud services introduced as backend complexity grows |
| Build output | Static HTML/CSS/JS | Generated by Astro at build time |

### Deployment phases
1. **Launch** — Fully static site deployed to Cloudflare CDN. No backend required.
2. **Growth** — Spring Boot microservices introduced for calculators that require server-side logic.
3. **Scale** — AWS services (compute, storage, managed databases) adopted progressively as traffic and complexity demand.

## Testing

| Layer | Tool | Purpose |
|---|---|---|
| Frontend — unit | [Vitest](https://vitest.dev/) | Unit tests for calculator logic (formulas, validations, edge cases) |
| Frontend — E2E | [Playwright](https://playwright.dev/) | End-to-end tests simulating real user interactions in the browser |
| Backend — unit | [JUnit 5](https://junit.org/junit5/) | Unit and integration tests for Spring Boot microservices |

### Testing philosophy
- **Vitest** validates that the math is correct (formula-level).
- **Playwright** validates that the UI behaves correctly (interaction-level).
- **JUnit** validates that backend services return correct results and handle errors properly.

## Summary

```
Browser
  └── Astro (SSG) + Tailwind CSS

Cloud (Phase 2+)
  └── AWS
```
